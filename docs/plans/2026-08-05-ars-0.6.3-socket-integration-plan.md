# Sachima × agent-run-supervisor 0.6.3 Socket Integration Plan

> **Status:** Architecture proposal; implementation is not authorized by this document.
>
> **Baseline:** Sachima `release/sachima` at `9ba340518d1b817bb42636f50a28095bf6d50f81`; agent-run-supervisor `main` at `cde703369400bf0a62504f018a82d33ed8d311d7` / package `0.6.3`.
>
> **Scope:** Integrate Sachima with the independently managed `arsd` daemon through the official `ArsdClient` and Socket API v2 while preserving Sachima's Runtime Spine authority, default-off posture, and existing fake/library modes.

## 1. Executive decision

Sachima should consume ARS 0.6.3 as an external local execution plane, not as a Gateway-owned subprocess and not by replacing the Runtime Spine:

```text
Sachima TaskRegistry / TaskEventLog / StatusProjection
                         │
                 ExecutionPort
                         │
             SupervisorTurnDispatcher
              ├── fake backend (default)
              ├── library backend (compatibility / rollback)
              └── arsd backend (new, explicit)
                         │
              ArsdClient / Socket API v2
                         │
              operator-managed arsd 0.6.3
                         │
            registered external AGENT / ACP
```

The integration must preserve these ownership boundaries:

- Sachima owns task identity, admission, workspace lease, canonical task-event sequence, status projection, and user-visible state.
- `arsd` owns external AGENT process/session/run lifecycle, request admission, native event persistence, liveness observation, permission mediation, cancellation, and native execution evidence.
- Gateway renders and exposes explicitly approved query surfaces; it does not start, stop, restart, or supervise `arsd`.
- ARS event sequence is a foreign read-model cursor. It never becomes Sachima `TaskEventLog.seq`.

## 2. Current source facts

### 2.1 Sachima baseline

Sachima currently provides:

- `ExecutionPort` with `create_or_attach`, `stream`, `signal`, `status`, `kill`, and `liveness`.
- `AgentRunSupervisorPort`, which adapts an injected supervisor backend to Runtime Spine semantics.
- `AgentRunSupervisorLibraryBackend` and `AgentRunSupervisorTurnDispatcher`, currently coupled to the 0.1.7-style in-process session/turn model.
- `LiveProgressSourceBindings`, currently binding a task/session to a private `artifact_dir`, safe `artifact_ref`, and foreign cursor.
- LS4-A default-off internal query/display gates.
- Gateway backend modes `fake | library`; `fake` is the default.
- Exact optional dependency `agent-run-supervisor==0.1.7` in both the ARS extra and the development extra.

The existing library flow is:

```text
create/attach persistent Session -> send one turn -> read private turn artifacts
```

### 2.2 ARS 0.6.3 baseline

ARS 0.6.3 provides official `ArsdClient` operations:

- `server_info`
- `submit`
- `run_status`
- `run_events`
- `run_cancel`
- `session_status`
- `session_list`
- `session_close`

Protocol facts:

```python
ARSD_API_VERSION = 2
SUPPORTED_API_VERSIONS = (1, 2)
V2_ONLY_OPERATIONS = frozenset({"submit"})
```

`server_info` reports package/API versions and daemon limits. `submit` accepts a closed request shape and returns `run_id` plus `accepted_at`. Run event pagination returns:

```text
events
next_from_seq
exhausted
```

ARS persists native Run evidence and enforces owner/namespace authorization, stable request-id admission, request-digest idempotency, registered `agent_id` selection, model/effort fidelity, workspace binding, frozen grant material, and bounded run limits.

### 2.3 Compatibility observation

An isolated test environment using a locally built ARS 0.6.3 wheel ran the existing Sachima library-backend, turn-dispatcher, and execution-binding focused suites successfully: `152 passed`.

This supports retaining `library` as a compatibility/rollback mode under the single installed 0.6.3 distribution. It does not prove the new daemon path.

## 3. Non-goals and non-approvals

This plan does not authorize:

- enabling `arsd` mode by default;
- production configuration changes;
- Gateway/service restart or deployment;
- Gateway ownership of daemon/socket/subprocess lifecycle;
- real external ingress or result delivery;
- write-capable AGENT roles;
- public network listeners;
- bypassing ARS caller authentication, owner/namespace policy, registered-agent policy, or frozen grants;
- copying prompts, raw model text, stderr, tool output, credentials, platform IDs, socket paths, or private artifact paths into Sachima durable/user-visible state;
- treating supervisor terminal state as the business verdict;
- silently falling back from `arsd` to library/direct CLI after a daemon-path failure.

## 4. Dependency and deployment model

### 4.1 Sachima package

Update the optional and development pins together:

```toml
agent-run-supervisor = ["agent-run-supervisor==0.6.3"]
dev = [..., "agent-run-supervisor==0.6.3"]
```

Also update:

- `uv.lock`;
- `EXPECTED_AGENT_RUN_SUPERVISOR_VERSION`;
- package metadata and pin-consistency tests;
- the repository's package-date policy so the 2026-08-04 release is intentionally admissible.

The existing `exclude-newer-package` policy currently filters out 0.6.3 because its cutoff predates the release. The implementation must update that governed cutoff explicitly rather than bypass it in an undocumented command.

Sachima only needs the base distribution for `agent_run_supervisor.arsd.client.ArsdClient`.

### 4.2 Daemon package

The operator-managed daemon environment uses:

```text
agent-run-supervisor[native]==0.6.3
```

It owns the ACP SDK dependency and registered-agent configuration. Sachima must not inject executable paths, argv, environment values, or credentials through the Socket API.

### 4.3 Runtime lifecycle

`arsd` remains an external systemd-managed service. Sachima/Gateway may probe `server_info`, but must never start, restart, stop, or replace the daemon as part of normal request handling.

## 5. Sachima interface changes

### 5.1 Generalize the turn backend contract

The current dispatcher rejects any backend whose concrete type is not `AgentRunSupervisorLibraryBackend`. Replace that concrete coupling with a small, validated contract owned by Sachima, for example:

```python
class SupervisorTurnBackend(Protocol):
    def create_or_attach(self, task_id: str, refs: tuple[str, ...]) -> str: ...
    def attach_existing(self, task_id: str) -> str: ...
    def run_turn(
        self,
        task_id: str,
        *,
        turn_kind: str,
        payload_text: str,
        dispatch_ref: str,
    ) -> SupervisorTurnResult: ...
    def status(self, handle: str) -> str: ...
    def signal(self, handle: str, decision_ref: str) -> str: ...
    def kill(self, handle: str, reason_ref: str) -> str: ...
    def liveness(self, handle: str) -> str: ...
```

Use an explicit constructor/factory allowlist for `fake`, `library`, and `arsd`; do not accept arbitrary duck-typed objects at the production composition root.

`SupervisorTurnResult` must be transport-neutral. It should carry safe references and observations, not a library-specific `turn_dir`:

```text
run_ref
source_kind
source_ref
supervisor_status
foreign_cursor
```

For the arsd implementation, `run_turn` is a submit operation: it returns after durable acceptance with `supervisor_status="accepted"`. It does not block until the external AGENT reaches a terminal result. Trusted terminal state is observed later through `status()` / reconciliation. The transport-neutral status vocabulary is:

```text
accepted | completed | failed | cancelled | timed_out | unknown
```

The dispatcher single-flight window covers submit/admission only; Sachima separately enforces at most one active Run per task/session binding.

The existing library result is adapted into this neutral shape. The new arsd result uses `run_id` as a private locator and derives a safe `run_ref`/`artifact_ref` for projections.

The generalization must remove both concrete-type couplings: the check in `AgentRunSupervisorTurnDispatcher` and the `AgentRunSupervisorExecutionBinding.__post_init__` check that currently requires `AgentRunSupervisorLibraryBackend` exactly.

### 5.2 Add `ArsdSupervisorConfig`

The frozen config should contain only host-owned/private mappings and stable policy references:

```text
type
enabled (default False)
approval_ref
socket_path (private, repr/serialization excluded)
expected_package_version = 0.6.3
required_api_version = 2
owner
namespace
agent_by_policy_ref
model_by_policy_ref
effort_by_policy_ref
workspace_by_ref
run_limits_by_policy_ref
grant material/hash refs
MCP/evidence/recovery policy hash refs
```

Construction fails closed unless `enabled is True`, the config type is exact, paths/refs are valid, and all maps are owned immutable copies. No raw credential value belongs in this config.

### 5.3 Add an injected client facade

`ArsdSupervisorBackend` should depend on an injected `ArsdClientFacade` for tests. The default facade lazily imports and opens the official `ArsdClient` per bounded operation.

Do not retain one shared Socket client indefinitely:

- ordinary request/response calls use short-lived connections;
- follow subscriptions close their connection when the subscription ends;
- closing a follow connection never cancels the Run;
- a fresh client is used after connection loss.

### 5.4 Preflight negotiation

Before the first submit in a composed backend, call `server_info()` and verify:

```text
version == 0.6.3
api_version == 2
2 in supported_api_versions
submit in v2_only_operations
required limits are present and compatible
```

A package/API mismatch produces one stable Sachima backend-unavailable code. It must not fall back silently.

## 6. Submit contract and identity mapping

### 6.1 Stable request identity

Every submitted turn needs a stable `request_id` derived from an admitted Sachima dispatch identity, not from wall-clock time:

```text
(task_id, session_id, dispatch_ref) -> stable request_id
```

A retry of an uncertain submission reuses the same `request_id` and byte-equivalent request digest. ARS returns `IDEMPOTENCY_CONFLICT` if that ID is already bound to different material. Sachima must fail closed and surface a stable conflict code; it must not generate another ID and resubmit.

`retry_of_run_id` is used only by an explicit recovery decision, never as an automatic response to a socket timeout.

### 6.2 AgentRunRequest mapping

The admitted Sachima launch/policy material maps to ARS fields:

| ARS field | Sachima owner/source |
|---|---|
| `owner`, `namespace` | Fixed host caller policy |
| `agent_id` | Closed policy-ref → operator-registered agent mapping |
| `session_reuse`, `ars_session_id` | Private task/session binding ledger |
| `expected_binding_hash` | Carried compatibility field; ARS 0.6.3 does not execute it. Native binding enforcement remains daemon-owned. |
| `input_refs` | Evidence/blob claim checks only |
| `requested_model`, `requested_effort` | Closed role route selected before dispatch |
| `grant_ref`, `grant_hash`, `grant_role_hash`, `grant_capabilities` | Admitted frozen grant |
| `mcp_snapshot_hashes` | Precomputed config snapshots |
| `credential_refs` | References only, never values |
| `limits` | Policy-owned bounded limits |
| `evidence_policy_hash` | Admitted evidence policy |
| `recovery_policy_hash` | Admitted recovery policy |
| `schema_version` | Exactly ARS `SPEC_SCHEMA_VERSION` (`2` in 0.6.3) |

The outer submit payload contains:

```text
request
prompt_text
workspace_root
cwd
retry_of_run_id
```

`prompt_text`, paths, and request details remain private and must not be echoed through Sachima events or user-facing errors.

### 6.3 Session lifecycle

- First turn uses `session_reuse="none"`.
- In ARS 0.6.3 the first Run's deterministic native Session id is `{run_id}-ephemeral`; the backend derives it only from the accepted `run_id`, confirms it through trusted Session/Run observation, and records it in a private task/session ledger.
- Later turns use `session_reuse="reuse"` with that exact `ars_session_id` and the proven binding hash where required.
- Reuse additionally requires the registered AGENT to advertise `session/load`; otherwise the Run fails before prompt dispatch.
- Reuse failures such as missing Session or binding mismatch occur asynchronously as a failed Run after `submit` has returned a `run_id`; they are not synchronous submit errors.
- Unknown, closed, quarantined, or binding-drifted sessions fail closed.
- Re-attach never creates a replacement Session silently.

## 7. Event and progress integration

### 7.1 Do not read daemon artifact paths directly

The daemon's `native-runs/<run_id>` directory is ARS-owned implementation storage. The new Sachima path reads through:

```python
client.run_events(
    run_id,
    from_seq=cursor,
    limit=page_size,
    follow=False,
)
```

Initial implementation uses bounded pagination, not an unbounded resident follow loop.

### 7.2 Generalize `LiveProgressSourceBindings`

Current source binding assumes a private `artifact_dir`. Extend it additively with tagged private locators:

```text
artifact_file:
  private artifact_dir

arsd_run:
  private run_id
```

The serializable/public source remains refs-only:

```text
source_kind
artifact_ref / run_ref
last_seen_cursor
```

Neither `artifact_dir`, `run_id`, nor `socket_path` is serialized unless the project explicitly classifies `run_id` as a safe public ref; the conservative first implementation keeps it private and emits a derived safe ref.

### 7.3 Cursor translation

Translate ARS pagination fields at the adapter boundary:

```text
next_from_seq -> resume_cursor
exhausted     -> has_more = not exhausted
```

`from_seq` and Sachima's existing `after_seq` are both exclusive last-seen cursors. `next_from_seq` is the highest sequence returned on the page, so resuming with that value neither duplicates nor drops records. A byte-budget-truncated page may contain a synthetic truncation-marker event and report `exhausted=False`; validators and fixtures must preserve that shape.

The foreign cursor stays in the source-binding/read-model layer. It is never appended as Sachima's canonical event sequence.

### 7.4 Projection policy

Only closed structural data may cross into the workbench:

- stable event family/type;
- event count;
- safe status;
- text length/count metadata when already normalized and approved;
- cursor and exhaustion flags;
- safe refs.

Discard raw text, message bodies, tool payloads, stderr, exception text, child paths, and credential material.

## 8. Status, liveness, cancellation, and permission semantics

### 8.1 Status mapping

Suggested closed mapping:

| ARS observation | Sachima state |
|---|---|
| `accepted` / active progress | `running` |
| trusted `completed` terminal result | `completed` |
| trusted `failed` terminal result | `failed` |
| trusted `cancelled` terminal result | `cancelled` |
| trusted `timed_out` terminal result | `failed` |
| trusted `unknown` or durable but undecidable terminal evidence | `ambiguous` |
| missing/unreachable observation | backend read failure; do not mutate canonical state |
| invalid/untrusted terminal evidence | backend failure / contained; never fabricate success |

A socket disconnect means observation loss, not Run failure. Sachima retains the last canonical projection and retries observation through a fresh client when explicitly queried or reconciled.

### 8.2 Cancellation

`ExecutionPort.kill()` maps to `run_cancel(active_run_id)`. After cancellation, read trusted terminal status before projecting `cancelled`. If cancellation outcome is unavailable, report ambiguous/backend failure rather than claiming success.

Session closure is explicit and separate through `session_close(ars_session_id)`.

`session_close` is not wire-idempotent: closing an already closed Session returns `INVALID_REQUEST`. The adapter must treat an independently observed already-closed Session as the desired target state, while quarantined Sessions remain uncloseable and unreusable.

### 8.3 Permission decisions

Socket API v2 has no external `signal(decision_ref)` operation. ARS 0.6.3 mediates ACP permission requests from the frozen grant supplied at submit time.

Therefore the first arsd backend:

- admits only roles whose permissions are fully determined before submit;
- keeps `ExecutionPort.signal()` fail-closed for arsd mode;
- does not invent a `permission_wait -> running` transition;
- requires a separate ARS protocol extension before supporting operator-in-the-loop permission decisions.

## 9. Error model

Map typed `ArsdClientError.code` values into a small Sachima-owned stable set. At minimum distinguish:

- backend unavailable / connection failure;
- unsupported API/package version;
- invalid admitted request;
- owner/namespace mismatch;
- unknown Run or Session;
- idempotency conflict;
- concurrency/admission exhaustion;
- submission indeterminate;
- shutting down;
- internal/untrusted terminal failure.

Never forward remote error messages. ARS's official client already discards untrusted remote message text; Sachima should preserve that boundary and emit only local stable codes.

## 10. Gateway composition

Extend:

```text
SACHIMA_LIVE_PROGRESS_BACKEND=fake|library|arsd
```

Rules:

- unset/blank remains `fake`;
- `arsd` requires the existing exact `hermes_internal` surface gate;
- `arsd` additionally requires an explicit private config file;
- malformed/disabled config leaves the tool unbound and returns one stable code;
- composing the display service must not submit a Run;
- dispatch requires a separately injected payload resolver/admission path;
- no automatic fallback to `library` or direct CLI.

## 13. Rollback

Rollback is layered:

- **Runtime route rollback:** select `fake`; never silently select `library` after a daemon error.
- **Code rollback:** revert the exact integration commit/PR.
- **Package rollback:** restore the prior pin and lock together; do not keep mixed package metadata.
- **Daemon rollback:** operator-owned and separately authorized; Sachima never changes daemon lifecycle automatically.
- **In-flight Runs:** record and reconcile by Run ID before changing routes. A route rollback does not imply cancellation.

## 14. Principal risks and decisions

| Risk | Decision |
|---|---|
| Treating package 0.6.3 as proof of API v2 | Require `server_info()` negotiation before submit. |
| Replacing Sachima event authority with ARS events | Keep ARS sequence as foreign cursor/read model only. |
| Reusing library-specific `turn_dir` contract | Introduce transport-neutral turn result and tagged source locator. |
| Duplicating or replaying an uncertain submit | Stable request ID + identical digest; conflict fails closed. |
| Reporting socket loss as Run failure | Preserve prior projection and report observation failure. |
| Dynamic permission approval assumed available | Keep `signal()` closed; frozen-grant mediation only. |
| Gateway accidentally owns daemon lifecycle | External systemd ownership is invariant. |
| Two incompatible ARS versions in one environment | One 0.6.3 distribution; library compatibility is tested under that version. |
| Silent fallback hides broken arsd path | No automatic arsd -> library/direct CLI fallback. |

## 15. Recommended approval boundary

The smallest next implementation authorization should cover **D0 + D1 only**:

- package/lock/date-policy migration to 0.6.3;
- preservation of current fake/library behavior;
- offline Socket API v2 adapter and contract tests;
- no real daemon submission, Gateway change, deployment, or external AGENT execution.

D2 and each later slice should be accepted separately after the preceding contract is proven.
