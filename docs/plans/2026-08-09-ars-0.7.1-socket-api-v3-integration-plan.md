# Sachima × agent-run-supervisor 0.7.1 — arsd Socket API v3 Implementation Plan

> **Type:** Implementation plan (candidate). Docs-only until separately approved.
> **Governing Spec:** `docs/plans/2026-08-09-ars-0.7.1-socket-api-v3-integration-spec.md` (accepted).

## 1. Goal

Migrate Sachima from the removed `agent-run-supervisor` **library** backend to an operator-managed **`arsd` 0.7.1 daemon over Socket API v3 / Native ACP**, default-off and fully offline-testable, without a silent fallback and without fabricating terminal truth.

The deliverable is a usable integration: one admitted Sachima turn becomes exactly one durable ARS Run under a Sachima-derived idempotent `request_id`; Sachima privately and **durably** binds that dispatch to `(run_id, ars_session_id)` so observation resumes after a restart without re-dispatching; later turns reuse the same durable ARS Session; and user-visible status moves only on trusted Run terminal evidence.

Nothing in this plan turns `arsd` on, runs a real AGENT, or touches Gateway runtime, delivery, or production. `fake` stays the default and stays green.

## 2. Architecture

Five layers, each with one owner. The migration changes the two middle layers and leaves the outer two intact.

```text
Sachima canonical spine        TaskRegistry / TaskEventLog (single seq authority)
                               Status Projection: created|running|permission_wait|
                                                  completed|failed|cancelled
        ▲ (canonical status only; never a raw id, never a foreign cursor)
        │
Runtime Spine port layer       AgentRunSupervisorPort / ExecutionPort
                               session states: running|permission_wait|completed|
                                               failed|cancelled|ambiguous|orphaned
        ▲ (neutral backend protocol + exact-type factory allowlist)
        │
Neutral turn seam  [NEW]       SupervisorTurnBackend / SupervisorTurnResult
                               transport vocabulary: accepted|completed|failed|
                                                     cancelled|timed_out|unknown
        ▲                                          ▲
        │                                          │
Backends            fake (default, no ARS import)  ArsdSupervisorBackend  [NEW]
                                                          │
Private identity    ArsdRunBindingLedger [NEW, durable]   │  ArsdClientFacade
                    (task_id, session_id, dispatch_ref)   │  (7 ops, v3 envelope)
                        -> (run_id, ars_session_id, ...)  ▼
                                                   operator-managed arsd daemon
```

Two invariants shape every stage:

- **Foreign data never becomes canonical data.** `run_id`, `ars_session_id`, `next_from_seq`, and remote `error.message` live in private, `repr=False`, non-serializable fields. Public surfaces carry only Sachima-derived `run_ref` / `source_ref` / `artifact_ref` and Sachima-owned stable codes.
- **Absence of observation is not evidence of failure.** Disconnects, unreadable replies, and daemon restarts mark the *observation* failed and leave canonical state untouched.

## 5. Spec-review closures

The Spec review raised six non-blocking items. Each is resolved here with a source-backed decision and a test that cannot pass vacuously.

### R-1 — Durable home for the private binding ledger

**Problem.** Spec §7.3 requires a restart-safe private binding. `TaskEventLog` is forbidden for raw ids (Spec §9.5), and the existing `LiveProgressSourceBindings` (`sachima_supervisor/runtime_spine/live_progress_sources.py:249-267`) is an **in-memory** store — `_bindings: dict[...] = field(default_factory=dict, init=False)`. Neither can hold the binding.

**Decision.** A new, purpose-built durable module: `sachima_supervisor/runtime_spine/arsd_run_binding_ledger.py`.

- One host-owned private JSON file, absolute, outside the tracked repo, supplied by a new `ArsdSupervisorConfig.binding_ledger_path` (private, `repr=False`, validated by the existing `_private_abs_path` boundary).
- Writes are atomic: serialize → write temp sibling → `os.replace`. A torn or unparseable file fails closed with `runtime_invalid_arsd_binding`; it is never silently reset.
- Record fields: public `task_id`, `session_id`, `dispatch_ref`, `request_id`, `run_ref`, `payload_digest`, `accepted_at`; private `run_id`, `ars_session_id` (`repr=False`, absent from `as_dict()`).
- Responsibilities stay split: the **ledger** owns durable identity; `LiveProgressSourceBindings` keeps owning the in-memory read-model position (`source_kind`, `artifact_ref`/`run_ref`, `last_seen_cursor`). This is not duplication — one is identity, one is cursor state.

**Restart-safe test (non-vacuous by construction).** `test_second_ledger_instance_resumes_without_redispatch`: instance A binds a record; instance A is dropped; a **fresh** `ArsdRunBindingLedger` is constructed over the same path with a facade double whose `submit` raises on call; `resolve()` returns the identical `run_id`/`ars_session_id` and observation proceeds. If any code path re-dispatched, the facade double fails the test.

### R-2 — One key contract

**Problem.** Spec §7.1 derives `request_id` from `(task_id, session_id, dispatch_ref)`; Spec §7.3 writes the ledger key as `(task_id, dispatch_ref)`.

**Decision.** The ledger key is the **full triple**, identical to the `request_id` derivation inputs. Source basis:

- `derive_arsd_request_id(task_id, session_id, dispatch_ref)` — `sachima_supervisor/runtime_spine/arsd_socket_contract.py:521` — takes exactly three components.
- The dispatcher requires a `sess_`-prefixed Sachima spine session id (`agent_run_supervisor_turn_dispatcher.py:105-108`), and `AgentRunSupervisorPort.create_or_attach` can mint a **new** spine `session_id` for the same `task_id` across a reconstruct/attach cycle. `(task_id, dispatch_ref)` is therefore not unique over a task's lifetime and would alias two distinct dispatches onto one binding.

`request_id` is stored on the record as a **derived witness**, not a second key. The redundancy is exactly what makes the contract checkable.

**Tests.** `test_binding_key_is_exactly_the_request_id_derivation_inputs` — for every stored record, `derive_arsd_request_id(*key) == record.request_id`, and a record whose stored `request_id` disagrees fails closed on read. `test_same_dispatch_ref_under_two_spine_sessions_binds_two_records` — the alias the two-component key would have created is proven absent.

### R-3 — `turn_dir` removal cannot pass vacuously

**Problem.** Introducing a neutral result type while the old field survives would satisfy A-19's letter and none of its intent. Note also that `SupervisorTurnResult` does **not exist** at this baseline — the concrete type is `LibraryTurnResult`, and it carries `turn_dir`.

**Decision.** An enumerated coupling inventory (§9.1, table C) plus a repo-wide absence guard:

`test_no_turn_dir_reference_in_runtime_source` — greps every `*.py` under `sachima_supervisor/`, `gateway/`, and `scripts/` for the **bare identifier** `turn_dir` (exact semantics in §9.2) and asserts zero hits. Adding a new neutral type without deleting `LibraryTurnResult.turn_dir` (`agent_run_supervisor_library_backend.py:417`), the dispatcher's `result.turn_dir` (`agent_run_supervisor_turn_dispatcher.py:331`), the facade tuple (`:889`), or the activity's `Path(outcome.turn_dir).iterdir()` (`activity_session_real_execution.py:482`) fails that test. All four sites are closed in P3, so the guard never waits on a later stage.

The concrete-type couplings are covered by the same stage: `type(backend) is not AgentRunSupervisorLibraryBackend` (`agent_run_supervisor_turn_dispatcher.py:261`), `type(result) is not LibraryTurnResult` (`:396`), and the frozen bundle's `backend: AgentRunSupervisorLibraryBackend` + `__post_init__` type check (`agent_run_supervisor_execution_binding.py:67,77`).

### R-4 — `MAX_ERROR_MESSAGE_CHARS` in the drift-lock decision

**Problem.** Spec §5.2 names four bounds Sachima "mirrors and drift-locks", but B-4 enumerates only five constants and omits `MAX_ERROR_MESSAGE_CHARS`. Sachima also discards remote `message` entirely (§9.5, §13.1), so a naive mirror would have no consumer.

**Decision: mirror it and drift-lock it**, with exactly one real consumer so it is not speculative surface.

- Add `ARSD_MAX_ERROR_MESSAGE_CHARS = 512` to the mirror set; drift-lock it against `agent_run_supervisor.arsd.protocol.MAX_ERROR_MESSAGE_CHARS` alongside the other five (verified present at `arsd/protocol.py:34`).
- Consumer: the adversarial **discard witness**. `test_remote_error_message_at_the_contract_maximum_is_fully_discarded` builds a client-error double whose `message` is a leak-marker string of exactly `ARSD_MAX_ERROR_MESSAGE_CHARS` characters — the true wire maximum — and proves not one byte reaches any exception message, repr, projection, or serialized surface. The mirror keeps that fixture pinned to the real maximum if ARS ever raises the bound.

This makes §5.2 and B-4 consistent rather than leaving a documented-but-unmirrored constant.

### R-5 — `session_list` response shape

**Fact (verified in 0.7.1 source, `arsd/handlers.py:1477-1488`).** `_session_list` returns `{"sessions": [ <session_view>, ... ]}`. `_session_view` is exactly `{session_id, owner, namespace, agent_id, profile_id, created_at, updated_at, last_effective_model, last_effective_effort, quarantine}`.

**Decision.** Two validators, not one:

- `validate_arsd_session_view(payload) -> ArsdSessionView` — exact ten-key set, `quarantine` is `None` or exactly `{reason_code, source_run_id, recorded_at}` with `reason_code` in the closed five-member mirror (`DISPATCH_OBSERVATION_LOST`, `DISPATCH_WITHOUT_TRUSTWORTHY_TERMINAL`, `UNTRUSTED_TERMINAL_EVIDENCE`, `SWITCH_ROLLBACK_UNPROVEN`, `RECONCILED_DISPATCH_WITHOUT_TERMINAL`), drift-locked against `agent_run_supervisor.session.QUARANTINE_REASON_CODES` and `QUARANTINE_EVIDENCE_FIELDS`.
- `validate_arsd_session_list(payload) -> tuple[ArsdSessionView, ...]` — top-level key set exactly `{"sessions"}`, value a `list`, each element through the view validator.

**Negative tests that pin the top level** (`test_session_list_rejects_a_bare_session_record`, `test_session_list_rejects_a_non_list_sessions_value`, `test_session_list_rejects_extra_top_level_keys`) plus `test_session_list_accepts_an_empty_session_page`. A bare session record at the top level is a protocol violation, never a tolerated shape.

### R-6 — Transport-terminal vocabulary vs. Sachima canonical vocabulary

**Fact.** These are four distinct closed vocabularies in the current tree:

| Layer | Vocabulary | Source |
|---|---|---|
| ARS Native ACP terminal | `completed`, `failed`, `cancelled`, `timed_out`, `unknown` | `agent_run_supervisor.exit_classifier.AgentRunStatus` (exactly five members) |
| Transport-neutral (new seam) | `accepted`, `completed`, `failed`, `cancelled`, `timed_out`, `unknown` | Spec §8.3 |
| Sachima port / session state | `running`, `permission_wait`, `completed`, `failed`, `cancelled`, `ambiguous`, `orphaned` | `execution_port.py:21-34` |
| **Sachima canonical status** | `created`, `running`, `permission_wait`, `completed`, `failed`, `cancelled` | `events.py:156-158` (`STATUS_VALUES`; `:159` is the separate `TERMINAL_STATUSES`) — **no `timed_out`, no `unknown`, no `ambiguous`** |

**Decision.** The mapping is explicitly three-hop, and the boundary between hop 2 and hop 3 is the thing under test:

```text
ARS terminal      transport-neutral      port session state      canonical status
completed    ->   completed         ->   completed          ->   completed
failed       ->   failed            ->   failed             ->   failed
cancelled    ->   cancelled         ->   cancelled          ->   cancelled
timed_out    ->   timed_out         ->   failed             ->   failed
unknown      ->   unknown           ->   ambiguous          ->   failed
```

The last column already exists: `agent_run_supervisor_port.py:88` maps backend `ambiguous` to session state `ambiguous`, and `_terminal_event_body` (`:788-790`) projects that as canonical `failed`. So `timed_out` and `unknown` converge on canonical `failed` through **different** session states — observable at `SessionStatus.state`, which is exactly what makes A-12's "proven independently" satisfiable.

**Tests.** `test_transport_terminal_vocabulary_is_disjoint_from_canonical_status_values` (asserts `timed_out`/`unknown`/`accepted` are absent from `events.STATUS_VALUES`, so a transport token can never be appended as a canonical status), and `test_each_ars_terminal_maps_through_all_three_hops` — one parametrized row per terminal asserting the transport token, the resulting `SessionStatus.state`, and the canonical `TaskEventLog` status, all three.

## 10. Stage P4 — `arsd` backend: submit, observe, cancel, terminal truth

**Objective.** A default-off `arsd` backend that submits once, observes honestly, cancels precisely, and never fabricates an outcome.

### P4 tasks

**P4-a — New module** `sachima_supervisor/runtime_spine/arsd_supervisor_backend.py`:

- `ArsdSupervisorBackend(config, facade, ledger)` — constructing it *is* the gate: `require_enabled_arsd_supervisor_config` fails closed unless `enabled` is exactly `True`.
- **Preflight.** Before the first submit of a composed backend, one `server_info` negotiation through `validate_arsd_server_info`. A failure is a single stable backend-unavailable verdict; there is no fallback to library, CLI, `acpx`, or another API version.
- **Submit.** `run_turn` derives `request_id`, builds the payload, records the digest, submits, validates the three-key ack, and writes the ledger record (`run_id` + `session_id` + `accepted_at`). It returns `supervisor_status="accepted"` and does **not** block until the AGENT terminates (Spec §8.3).
- **Create vs. reuse.** First turn omits `session_id`; later turns of the same task pass the recorded id verbatim. A quarantined or unknown Session is never auto-healed, auto-recreated, or retried into.
- **Observe.** `status()` reads `run_status` and applies the R-6 three-hop mapping. An observation failure returns a transient stable code and mutates nothing.
- **Cancel.** `kill()` issues exactly `run_cancel(active_run_id)` — never a Session operation. `cancelled` projects only on trusted terminal evidence; otherwise a bounded re-query, then `ambiguous` / observation-failure. A successful cancel is never claimed unproven.
- **Permissions.** `signal()` stays fail-closed in `arsd` mode; no `permission_wait` → `running` transition is invented (Spec §10.6). Grants stay on the read/search allowlist.
- **Indeterminate submit.** Maps to `runtime_arsd_submission_indeterminate`, marks the ledger slot fail-closed, and performs **no** automatic replay and **no** new `request_id`.

## 13. Definition of Done

The implementation is done when **all** of the following hold:

1. Every row A-1 … A-21 and B-1 … B-10 has a passing test at the path named in §12, and every drift lock runs for real against the installed extra in CI rather than skipping.
2. All six review closures R-1 … R-6 are satisfied by the named tests, including the two anti-vacuity guards (`test_no_turn_dir_reference_in_runtime_source`, `test_no_retired_agent_run_supervisor_module_references`).
3. `fake` is the default, is green, and imports no `agent_run_supervisor` on any code path.
4. `arsd` is default-off and unreachable without exact `enabled=True`, the `hermes_internal` surface gate, and an explicit private config file.
5. `library` fails closed with its own distinct stable migration code naming `fake`/`arsd`; no rewrite, no fallback, no dispatch, nothing bound.
6. The whole acceptance suite is pure and offline: no daemon, socket, real AGENT, network, Gateway, Temporal Worker, or service lifecycle anywhere.
7. Full offline suite green apart from the pre-existing worktree-diff guards named in §11; `uv lock --check` clean; `ruff` and `ty` clean on changed files; `git diff --check` clean.
8. `docs/roadmap/current-status.md` reflects the new task state, and `docs/roadmap/boundary-register.md` remains accurate.
9. Open gates E-1 … E-7 remain explicitly open and unclaimed. E-8 is resolved by §11.1.

Reaching Definition of Done does **not** approve enabling `arsd`, running a canary, or any of §4.2.
