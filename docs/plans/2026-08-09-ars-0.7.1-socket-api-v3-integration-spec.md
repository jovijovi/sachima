## 2. Business objective and success definition

### 2.1 Objective

Sachima must be able to run real external AGENT work through an **operator-managed** `arsd` daemon over a local Unix socket, while Sachima remains the authority for everything the product is judged on.

The division of authority is the whole point of the integration:

| Authority | Owner |
|---|---|
| `task_id`, durable workflow state, `TaskEventLog` sequence, Status Projection, user-visible business status | **Sachima** |
| Run execution, Session durability, ACP permission mediation, terminal evidence trust, local artifact storage, daemon lifecycle | **ARS / operator** |

ARS is an execution and evidence boundary. It is never a source of Sachima's canonical sequence, and never a source of user-visible text.

### 2.2 Success definition

The integration is successful when all of the following hold:

1. One admitted Sachima turn produces exactly one durable ARS Run, identified by a Sachima-derived idempotent `request_id`.
2. Sachima privately binds `(task_id, dispatch) → (run_id, session_id)` and can resume observation of that Run after a process restart without re-dispatching.
3. Later turns of the same task reuse the same durable ARS Session; a Session is never closed by Sachima and never silently replaced.
4. Sachima's user-visible status derives only from trusted Run terminal evidence or from Sachima's own state — never from a socket-level event, a foreign cursor, or a raw remote message.
5. Observation loss (disconnect, daemon restart, unreadable reply) never becomes a fabricated Run failure and never mutates canonical task state.
6. `kill` cancels the active Run only, and reports `cancelled` only on trusted terminal evidence.
7. No prompt, model text, tool payload, stderr, credential, private socket path, raw remote error, or daemon run directory reaches any Sachima event, projection, log, serialized state, or user surface.
8. Selecting the retired `library` mode fails closed with a stable migration error naming the supported choices.

### 2.3 Non-success (explicitly not a goal of the integration itself)

Turning `arsd` on, running a real AGENT, wiring Gateway, or shipping a user-facing feature. Those are separate approvals downstream of a working, proven contract.

## 5. API v3 protocol and closed contracts

### 5.1 Closed operation set

Socket API v3 is the **only** supported wire version. Exactly seven operations exist:

```text
server_info  submit  run_status  run_events  run_cancel  session_status  session_list
```

There is no `session_close`. Sachima must model the operation set as a closed frozen set and must never send an operation outside it.

### 5.2 Envelope and framing

```text
request  : {api_version: 3, op: <one of the seven>, request_id: <[A-Za-z0-9._-]{1,128}>, payload: {...}}
result   : {request_id, result: {...}}
error    : {request_id | null, error: {code, message}}
```

Bounds Sachima mirrors and drift-locks: frame ≤ 1 MiB, prompt ≤ 256 KiB, JSON container nesting ≤ 64, error message ≤ 512 chars.

The version verdict is taken on the **envelope**, before the operation is resolved. There is no per-operation version matrix and no drain window.

### 5.3 `server_info` negotiation

Result shape is exactly:

```text
version                 # package version string
api_version             # 3
supported_api_versions  # [3]
operations              # the sorted seven
limits: {max_concurrent_runs, max_frame_bytes, max_prompt_bytes,
         events_page_limit, event_follow_queue_size}
```

Sachima's preflight, before the first submit of a composed backend, verifies:

| Check | Verdict on failure |
|---|---|
| Result is a mapping whose key set is exactly the five keys above | `runtime_arsd_protocol_violation` |
| `limits` key set is exactly the five limit keys; every value a non-bool int | `runtime_arsd_protocol_violation` |
| `version == expected_package_version` (`0.7.1`) | `runtime_arsd_version_mismatch` |
| `api_version == 3` | `runtime_arsd_version_mismatch` |
| `supported_api_versions == (3,)` exactly | `runtime_arsd_version_mismatch` |
| `operations` equals the closed seven-operation set exactly | `runtime_arsd_version_mismatch` |
| `max_frame_bytes` / `max_prompt_bytes` equal the mirrored protocol constants | `runtime_arsd_version_mismatch` |
| `max_concurrent_runs`, `events_page_limit`, `event_follow_queue_size` are usable and bounded | `runtime_arsd_version_mismatch` |

Only the exact mirrored values reach the repr-safe observation object, so no remote string survives into a diagnostic surface. A mismatch is a single stable backend-unavailable verdict. **There is no silent fallback** to library, CLI, `acpx`, or a different API version.

### 5.4 Closed wire error set

Seventeen codes, unchanged from 0.6.3:

```text
UNSUPPORTED_API_VERSION  UNKNOWN_OP  MALFORMED_FRAME  FRAME_TOO_LARGE  INVALID_REQUEST
UNAUTHENTICATED_PEER  PEER_UID_DENIED  OWNER_MISMATCH  IDEMPOTENCY_CONFLICT
SUBMISSION_INDETERMINATE  UNKNOWN_RUN  UNKNOWN_SESSION  SESSION_BUSY
CAPACITY_EXHAUSTED  EVENT_BACKLOG_EXCEEDED  SHUTTING_DOWN  INTERNAL
```

Plus the official client's local `CLIENT` code. Mapping to Sachima codes is §13.

## 6. Session no-close and Run lifecycle model

### 6.1 The model

**Runs terminate. Sessions do not close.**

- A **Session** is durable conversation continuity with one registered agent. It has identity, binding, and last-use observations — and deliberately **no lifecycle state to project**. It is never closed, by Sachima or by anyone.
- A **Run** is the terminal, disposable unit of work. Exactly one Run occupies a Session at a time; a concurrent Run against the same Session is refused with `SESSION_BUSY`.
- **Quarantine** is separate continuity evidence, not a lifecycle state. A quarantined Session still exists; it is refused for *reuse*.

### 6.2 Create vs. reuse — the only Session decision

The whole Session choice is the presence of `request.session_id`:

| Caller statement | Wire form | Daemon behavior |
|---|---|---|
| "I have no Session" | **key omitted** | Create one new durable Session, run its first Run |
| "Reuse exactly this Session" | key present, valid id | Existing-only reuse; never falls back to create |
| "My Session is null" | key present, `null` | **`INVALID_REQUEST`**, refused before any storage access |

This is a correctness rule, not a style rule: collapsing absent and present-null would let a Sachima code path whose id lookup returned `None` silently start a *second* conversation against the same agent. Sachima's submit builder must therefore construct the request dict with the `session_id` key **absent** on create — not present-and-`None`.

Sachima must never derive a "reuse mode" flag on the wire. There is no `session_reuse` field in schema 3.

### 6.3 Session id acquisition

Sachima learns the Session id from the **submit ack**, which carries it directly (§7.2). Sachima must not derive it, guess it, or reconstruct it from a `run_id` convention. The daemon's internal derivation for a create Run is daemon-private.

The id must satisfy `[A-Za-z0-9][A-Za-z0-9_\-]*` before Sachima sends it back on a reuse turn; anything else is a Sachima-side invalid-request failure, never a socket call.

### 6.4 Session state Sachima may observe

`session_status` / `session_list` project identity, last-use observations, and optional quarantine evidence:

```text
session_id  owner  namespace  agent_id  profile_id  created_at  updated_at
last_effective_model  last_effective_effort  quarantine
```

`quarantine` is `null` or exactly `{reason_code, source_run_id, recorded_at}` with `reason_code` from a closed five-member vocabulary. It is categorical by construction: no exception text, no agent text, no path.

Sachima treats a non-null `quarantine` as: **this Session is not reusable**. The task's continuity is broken and requires an explicit Sachima-side decision (start a new Session under a new dispatch, or surface a stable blocked status). Sachima must not auto-heal, auto-recreate, or retry into a quarantined Session.

### 6.5 Run terminal vocabulary

The Native ACP terminal vocabulary is exactly five members:

```text
completed  failed  cancelled  timed_out  unknown
```

Terminal evidence has exactly three trust kinds: **ABSENT**, **TRUSTED**, **INVALID**. Only TRUSTED evidence may move Sachima's canonical status. INVALID terminal evidence causes the daemon to contain the Run, quarantine the bound Session, and refuse with `INTERNAL` — Sachima maps that to a stable internal/contained failure and never fabricates an outcome (§10.5).

## 7. Identity, idempotency, and private Run+Session binding

### 7.1 Request identity

`request_id` is derived from the admitted Sachima dispatch identity only:

```text
(task_id, session_id, dispatch_ref) -> sachima-<sha256 hex>
```

Never from wall-clock time, never from a counter. A retry of an uncertain submission reuses the exact same `request_id` **and** a byte-equivalent payload (proven by `arsd_submit_payload_digest`, without persisting the payload). The daemon keys idempotency on `(principal_id, request_id)`; the same id with different material returns `IDEMPOTENCY_CONFLICT`.

On `IDEMPOTENCY_CONFLICT`, Sachima **fails closed** with a stable conflict code. It must not mint a new id and resubmit.

### 7.2 Submit ack

The ack is exactly:

```text
{run_id, session_id, accepted_at}
```

A duplicate submit under the same `request_id` returns the same three facts, read back from the durable submission, and dispatches nothing a second time.

### 7.3 Private binding ledger

On a successful ack, Sachima privately binds:

```text
(task_id, dispatch_ref) -> (run_id, session_id, accepted_at, request_id, payload_digest)
```

Rules:

1. **Both** `run_id` and `session_id` are private locators. Neither is public status text, neither is serialized into `TaskEventLog`, projections, view models, logs, or user-visible surfaces. Public surfaces carry only Sachima-derived safe refs (`run_ref`, `source_ref`).
2. The binding is what makes restart-safe resumption possible: after a Sachima restart, observation resumes from the recorded `run_id` — there is no re-dispatch.
3. `session_id` is recorded on the **first** turn and reused verbatim on later turns of the same task.
4. `retry_of_run_id` is populated only by an explicit operator/recovery decision, never as an automatic response to a timeout or a disconnect.

### 7.4 Concurrency

The daemon refuses a concurrent Run on a busy Session with `SESSION_BUSY`, including for a create Run tracked under its prospective Session id. Sachima additionally enforces **at most one active Run per task/session binding** on its own side; the dispatcher single-flight window covers submit/admission only, and must not be mistaken for a lock held for the duration of the Run.

## 8. Transport-neutral Runtime Spine interface implications

### 8.1 The neutral backend contract

The turn dispatcher and the execution binding currently require the concrete `AgentRunSupervisorLibraryBackend` type. Both concrete-type couplings must be replaced by one Sachima-owned validated contract:

```text
create_or_attach(task_id, refs) -> handle
attach_existing(task_id)        -> handle
run_turn(task_id, *, turn_kind, payload_text, dispatch_ref) -> SupervisorTurnResult
status(handle)   -> str
signal(handle, decision_ref) -> str
kill(handle, reason_ref)     -> str
liveness(handle) -> str
```

Backend construction goes through an explicit factory allowlist for `fake` and `arsd`. Arbitrary duck-typed objects are not accepted at a production composition root.

### 8.2 `SupervisorTurnResult` must lose `turn_dir`

The current result carries `turn_dir` — a library-private filesystem path. Daemon-private storage layout is **not caller contract** under this integration: `arsd` owns `native-runs/<run_id>` and Sachima must not read it, name it, or model it.

The neutral result carries safe references and observations only:

```text
run_ref          # Sachima-derived safe ref (never the raw run_id)
source_kind      # "arsd_run" | "artifact_file" (fake/offline)
source_ref       # safe ref for the read-model source
supervisor_status
foreign_cursor   # foreign read-model position; never TaskEventLog.seq
```

Every existing `turn_dir` consumer must be re-expressed against this neutral shape or dropped. Known consumers at this baseline: the library backend result type, the turn dispatcher's outcome construction, and the real-execution activity's artifact-count observation.

### 8.3 Transport-neutral status vocabulary

```text
accepted | completed | failed | cancelled | timed_out | unknown
```

`run_turn` for `arsd` is a **submit**: it returns after durable acceptance with `supervisor_status="accepted"`. It does not block until the external AGENT terminates. Terminal truth arrives later through `run_status` observation (§10).

### 8.4 Source bindings

`LiveProgressSourceBindings` currently assumes a private `artifact_dir`. It is extended additively with tagged private locators:

```text
artifact_file : private artifact_dir
arsd_run      : private run_id
```

The serializable/public projection stays refs-only: `source_kind`, `artifact_ref`/`run_ref`, `last_seen_cursor`. Neither `artifact_dir`, `run_id`, nor `socket_path` is ever serialized.

## 9. Events, cursors, projection, and no-leak

### 9.1 Read events through the socket only

Sachima reads run evidence exclusively via:

```text
run_events(run_id, from_seq=<cursor>, limit=<page_size>, follow=False)
```

Bounded pagination only. No resident `follow` subscription in the first implementation. No direct read of daemon run directories, ever.

### 9.2 Cursor translation

```text
next_from_seq -> resume_cursor
exhausted     -> has_more = not exhausted
```

`from_seq` and Sachima's `after_seq` are both **exclusive** last-seen cursors. `next_from_seq` is the highest sequence returned on the page, so resuming from it neither duplicates nor drops records. On an empty page it equals the request cursor.

A byte-budget truncation marker page carries exactly one synthetic marker event and reports `exhausted: false`. Validators and fixtures must preserve that exact shape.

### 9.3 The cursor is foreign — hard rule

The ARS event sequence is a **foreign read-model cursor**. It lives in the source-binding/read-model layer and is **never** appended as, mapped to, offset into, or reconciled with `TaskEventLog.seq`. Sachima's monotonic sequence authority is Sachima's alone.

### 9.4 Projection allowlist

Only closed structural data crosses into the workbench/projection:

- stable event family/type;
- event count;
- safe status;
- normalized, already-approved text length/count metadata;
- cursor and exhaustion flags;
- Sachima-derived safe refs.

Discarded without exception: raw text, message bodies, final messages, tool payloads, stderr, exception text, child/daemon paths, credentials, agent-authored text, remote error messages.

### 9.5 No-leak invariants

| Value | Rule |
|---|---|
| `socket_path` | private field, `repr=False`, no serialize surface, never logged |
| `prompt_text`, payload text | caller-owned wire material; goes to the facade `submit` and nowhere else |
| `run_id`, `session_id` | private locators; only derived safe refs are public |
| daemon run/session directories | never named, never read, never modeled |
| remote `error.message` | discarded at the client boundary; Sachima never re-reads it |
| workspace/cwd paths | private absolute paths outside the tracked repo; never serialized |

Every failure raises a Sachima `SpineError` whose message **is** the stable code.

## 10. Liveness, disconnect, cancellation, terminal truth, and quarantine

### 10.1 Status observation

`run_status` returns either an acceptance view (`{run_id, session_id, state: "accepted", accepted_at}`) or a body carrying optional `progress` and/or a trusted `result`.

| ARS observation | Sachima state |
|---|---|
| `accepted` / progress present, no terminal | `running` |
| trusted terminal `completed` | `completed` |
| trusted terminal `failed` | `failed` |
| trusted terminal `cancelled` | `cancelled` |
| trusted terminal `timed_out` | `failed` |
| trusted terminal `unknown` | `ambiguous` |
| observation unavailable (disconnect, unreadable, daemon down) | **backend read failure — canonical state is not mutated** |
| invalid/untrusted terminal evidence | contained backend failure; never a fabricated success |

### 10.2 Disconnect is observation loss

A socket disconnect, a daemon restart, or a failed read means Sachima *did not observe*. It does not mean the Run failed.

Required behavior: retain the last canonical projection, mark the observation attempt as failed with a stable transient code, and retry observation with a **fresh** client on the next explicit query or reconciliation. Never mark, kill, mutate, or re-dispatch on observation loss.

### 10.3 Indeterminate submission

A local transport loss *during a submit*, before a complete reply is read, is **indeterminate**: the daemon may already hold the Run. That outcome maps to `runtime_arsd_submission_indeterminate` and is surfaced for an explicit recovery decision.

There is **no automatic uncertain replay**. Recovery is: re-issue the *identical* `request_id` with a byte-equivalent payload (which the daemon resolves idempotently), or make an explicit operator decision. Never a fresh `request_id`, never an automatic `retry_of_run_id`.

### 10.4 Cancellation

`ExecutionPort.kill()` maps to exactly one operation: `run_cancel(active_run_id)`.

- It **never** closes a Session. There is no close.
- `run_cancel` returns `{run_id}`, plus `result`/`status` when trusted terminal evidence exists.
- Sachima projects `cancelled` only on trusted terminal evidence. If the outcome is not yet trusted, Sachima waits/re-queries `run_status` within its own bounded policy and otherwise reports `ambiguous` or a backend-observation failure. It never claims a successful cancel it cannot prove.
- Closing a follow connection or a client connection never cancels a Run.

### 10.5 Quarantine

Quarantine is continuity evidence, produced by the daemon when a Run's terminal evidence is untrusted or a dispatch cannot be proven. Sachima's obligations:

1. Read it only as the closed categorical structure from `session_status`/`session_list`.
2. Treat a quarantined Session as **not reusable**; a reuse attempt is refused pre-dispatch by the daemon with a stable detail code and no child, no prompt, no fallback Session.
3. Never project quarantine evidence as user-visible text; map it to a Sachima-owned stable blocked/ambiguous state.
4. Never attempt to clear, un-quarantine, or work around it. That is operator territory.

### 10.6 Permission decisions

Socket API v3 has no external `signal(decision_ref)` operation. ARS mediates ACP permission requests from the frozen grant supplied at submit time.

Therefore the first `arsd` backend:

- admits only roles whose permissions are fully determined **before** submit;
- keeps `ExecutionPort.signal()` fail-closed in `arsd` mode;
- does not invent a `permission_wait → running` transition;
- requires a separate ARS protocol capability before any operator-in-the-loop permission decision is possible.

Grant capabilities remain restricted to the read-only allowlist (`read`, `search`); write-capable grants stay fail-closed.

## 11. Legacy library / acpx retirement and explicit migration behavior

### 11.1 The fact

`agent-run-supervisor` 0.7.x removed the legacy library surface and the legacy `acpx` product. The modules Sachima's `library` mode imports lazily — `role`, `workspace`, `session_runtime`, `session_inspect`, `goal`, `caller`, `hermes_caller.events` — **do not exist** in 0.7.1. The `library` backend is therefore not degraded; it is unrunnable.

### 11.2 Required behavior — fail closed with a migration error

Selecting `library` (via config or `SACHIMA_LIVE_PROGRESS_BACKEND=library`) must:

1. **Fail closed** with one stable Sachima-owned migration code — a *distinct* code, not reused `runtime_arsd_unavailable` and not a generic invalid-config code, so the operator can tell "you selected a retired mode" from "the daemon is down".
2. Emit a stable, non-echoing message that names the supported choices: **`fake`** or **`arsd`**.
3. Leave the tool/service unbound, dispatch nothing, launch nothing, and mutate nothing.

### 11.3 Forbidden migration behaviors

- **No silent rewrite.** `library` must never be silently coerced to `fake` or `arsd`. A silent rewrite would run a different backend than the operator asked for.
- **No fallback.** No fallback to direct CLI, to the library, to `acpx`, or to `npx`.
- **No degraded emulation.** No attempt to reimplement `session_runtime`/`session_inspect` behavior against daemon-private storage.

### 11.4 Scope of retirement in Sachima

The retirement touches every place that reaches the removed modules: the library backend facade, the real-execution activity's default backend, the local-offline caller path, and the live-progress projection's caller-events reader. Each becomes either (a) re-pointed at the socket path, (b) fake/offline-only, or (c) explicitly retired with the stable migration error. Whether a given seam is (a), (b), or (c) is an implementation-plan decision; that every one of them stops depending on removed modules is a Spec requirement.

`fake` remains the default offline/dev mode and must stay fully functional with no `agent_run_supervisor` import at all.

## 12. Package, config, and daemon ownership

### 12.1 Package

`agent-run-supervisor` is consumed **only** as the installed exact-pinned distribution: `pyproject.toml` extra + mirrored `dev`, `EXPECTED_AGENT_RUN_SUPERVISOR_VERSION`, regenerated `uv.lock`, and a narrowed `[tool.uv].exclude-newer-package` entry. Zero source-path references — no `sys.path` shim, no sibling-checkout constant, no `PYTHONPATH` instruction — remains a guarded invariant.

Importing any Sachima module must never import `agent_run_supervisor` at module load. Only facade operations import it, lazily, inside the call.

### 12.2 Config

`ArsdSupervisorConfig` stays a frozen, default-off, host-owned config carrying private paths and closed policy-ref maps:

```text
type  enabled(default False)  approval_ref  socket_path(private)
expected_package_version = 0.7.1
required_api_version     = 3
owner  namespace
agent_by_policy_ref  model_by_policy_ref  effort_by_policy_ref
workspace_by_ref  run_limits_by_policy_ref
grant_ref  grant_hash  grant_role_hash  grant_capabilities
mcp_snapshot_hashes  credential_refs  evidence_policy_hash  recovery_policy_hash
```

Construction fails closed unless `enabled is True` (exactly the bool), the config type is exact, paths/refs are valid, private paths sit outside the tracked repo, and every map is an owned immutable copy. No raw credential value ever belongs here.

### 12.3 Gateway composition

```text
SACHIMA_LIVE_PROGRESS_BACKEND = fake | arsd     ("library" -> stable migration error, §11)
```

- unset/blank remains `fake`;
- `arsd` requires the existing exact `hermes_internal` surface gate **and** an explicit private config file;
- a malformed or disabled config leaves the tool unbound and returns one stable code;
- composing the display service must never submit a Run;
- dispatch requires a separately injected payload resolver/admission path;
- no automatic fallback to any other backend.

### 12.4 Daemon ownership — operator, not Sachima

Sachima and Gateway do **not** own any of the following. The operator does:

| Concern | Owner |
|---|---|
| Installing/activating the `agent-run-supervisor` package that runs the daemon | Operator |
| Starting, stopping, restarting `arsd`; the systemd user unit | Operator |
| The agents registry file (read exactly once at daemon startup) | Operator |
| Socket path, socket/dir permissions, peer→principal caller mappings | Operator |
| Supervisor root and daemon-private storage | Operator |
| Deploys, upgrades, and post-restart reconciliation | Operator |

Sachima is a caller. It connects to a socket that already exists; it never starts, restarts, provisions, or repairs the daemon, and it never writes daemon configuration. A registry or agent change costs an operator-owned daemon restart — Sachima must be correct across that restart, not attempt to trigger it.

## 13. Failure mapping — stable Sachima-owned categories

### 13.1 Principle

Sachima emits **only** its own stable codes. Remote `message` text is discarded at the client boundary and never re-read, re-raised, chained, stored, logged, or shown. The Sachima error's message **is** the code.

### 13.2 Mapping

| Wire code | Sachima stable code |
|---|---|
| `UNSUPPORTED_API_VERSION` | `runtime_arsd_version_mismatch` |
| `UNKNOWN_OP`, `MALFORMED_FRAME`, `FRAME_TOO_LARGE` | `runtime_arsd_protocol_violation` |
| `INVALID_REQUEST` | `runtime_arsd_invalid_request` |
| `UNAUTHENTICATED_PEER`, `PEER_UID_DENIED`, `OWNER_MISMATCH` | `runtime_arsd_policy_denied` |
| `IDEMPOTENCY_CONFLICT` | `runtime_arsd_idempotency_conflict` |
| `SUBMISSION_INDETERMINATE` | `runtime_arsd_submission_indeterminate` |
| `UNKNOWN_RUN`, `UNKNOWN_SESSION` | `runtime_arsd_unknown_target` |
| `SESSION_BUSY`, `CAPACITY_EXHAUSTED`, `EVENT_BACKLOG_EXCEEDED` | `runtime_arsd_busy` |
| `SHUTTING_DOWN` | `runtime_arsd_shutting_down` |
| `INTERNAL` | `runtime_arsd_internal` |
| client-local `CLIENT` | `runtime_arsd_unavailable` |
| unknown / wrong-type / casing-drifted code | `runtime_arsd_internal` (fail closed) |

Sachima-side codes not derived from the wire: `runtime_arsd_disabled`, `runtime_invalid_arsd_config`, and the new §11 migration code.

### 13.3 Operation-aware refinements

| Situation | Stable code | Why |
|---|---|---|
| Connect-phase failure | `runtime_arsd_unavailable` | Nothing was sent |
| Base-class client error with `INVALID_REQUEST` during a roundtrip | `runtime_arsd_protocol_violation` | Response-correlation failure (off-contract reply), not a daemon verdict on our request |
| Base-class transport loss (`INTERNAL`/`MALFORMED_FRAME`) **during a submit** | `runtime_arsd_submission_indeterminate` | The frame may have reached the daemon with its verdict unread |
| Same transport loss during a non-submit read | `runtime_arsd_unavailable` | Observation loss only (§10.2) |
| Close failure with no other active error | `runtime_arsd_unavailable` | Local hygiene failure |

### 13.4 Business-status boundary

None of these codes is user-visible text. They are Sachima-internal categories. The user-visible business status is produced by Sachima's Status Projection from Sachima-owned state, and stays inside the product vocabulary.

## 14. Acceptance matrix

All of this is **pure and offline**. No daemon, no socket, no real AGENT, no network, no service.

### 14.1 Contract tests (injected doubles + fixtures)

| # | Area | Must prove |
|---|---|---|
| A-1 | Import purity | Importing every touched module imports no `agent_run_supervisor` and opens no socket, at import or collection time |
| A-2 | `server_info` v3 | Exact-key acceptance; `api_version != 3`, `supported_api_versions != (3,)`, wrong package version, wrong/short/extra operation set, and bad limits each produce the exact expected stable verdict |
| A-3 | `v2_only_operations` removal | A payload still carrying `v2_only_operations` is a protocol violation, not a tolerated extra key |
| A-4 | Submit ack | Exactly `{run_id, session_id, accepted_at}` accepted; missing `session_id`, extra keys, or bad timestamp rejected; both ids land in private (`repr=False`) fields |
| A-5 | Session create | The built request dict **omits** the `session_id` key entirely; a builder call that would emit `session_id: null` is impossible/rejected |
| A-6 | Session reuse | A valid id is carried verbatim; an id violating `[A-Za-z0-9][A-Za-z0-9_\-]*` (including a dotted one) fails closed Sachima-side without a socket call |

| A-8 | Indeterminate submit | Transport loss during submit → `runtime_arsd_submission_indeterminate`; no automatic retry, no new `request_id` |
| A-9 | Pagination | Ascending-seq enforcement, exact `next_from_seq` semantics, empty-page cursor identity, and the standalone truncation marker with `exhausted: false` |

| A-11 | `run_status` shape | The acceptance view is exactly `{run_id, session_id, state: "accepted", accepted_at}`; the active view is exactly `{run_id, session_id}` plus optional `progress` and/or `result`. A missing, extra, or off-contract key — including a `state` value outside the contract — is a protocol violation, not a tolerated field |
| A-12 | Terminal truth mapping | On the **ordinary** observation path (no cancel issued, no transport failure), each trusted terminal maps exactly once and is proven independently: `completed` → `completed`, `failed` → `failed`, `cancelled` → `cancelled`, `timed_out` → **`failed`**, `unknown` → **`ambiguous`**. An absent terminal with progress present leaves the task `running` |
| A-13 | Untrusted terminal | Invalid/untrusted terminal evidence yields a contained backend failure (`runtime_arsd_internal`) — never a fabricated success, never a terminal business status, and never a projection of the untrusted payload |
| A-14 | Cancel | Distinct from A-12: `kill` issues `run_cancel` only and never any Session operation, and `cancelled` is projected only when trusted terminal evidence follows the cancel; an untrusted or not-yet-available outcome is ambiguous/observation-failure, never a claimed successful cancel |
| A-15 | Disconnect | Distinct from A-12/A-13 in that no terminal evidence is read at all: observation loss does not mutate canonical state, does not mark failure, and does not re-dispatch |
| A-16 | Quarantine | A non-null quarantine block blocks reuse and maps to a stable Sachima state; the categorical evidence never reaches a user-visible or serialized surface |
| A-17 | Error mapping | Every one of the 17 wire codes plus `CLIENT` maps to a stable code; unknown/mistyped codes collapse to internal; no remote text in any exception |
| A-18 | Legacy migration | `library` selection yields the distinct stable migration error naming `fake`/`arsd`; no rewrite, no fallback, no dispatch, nothing bound |
| A-19 | Neutral result | `SupervisorTurnResult` has no `turn_dir` and no daemon path; the concrete-type couplings in the dispatcher and the execution binding are gone |
| A-20 | No-leak sweep | Scan reprs, `str()`, serialized projections, event payloads, and exception text for socket path, prompt text, workspace paths, raw `run_id`/`session_id`, and remote message text |
| A-21 | Default-off | `arsd` is unreachable without an exact `enabled=True` config plus the surface gate; `fake` remains the default and stays green |

## 15. Non-goals and explicit non-approvals

### 15.1 Non-goals

- No compatibility shim for API v2, for the v2 request shape, or for old Session-close semantics. There is no external caller population to drain, and this environment has **no obligation** to preserve old locally persisted ARS state.
- No `session_close` emulation, no Session lifecycle projection, no "closed" state.
- No resident `follow` subscription in the first implementation.
- No operator-in-the-loop permission mediation over the socket.
- No reading, mirroring, or modeling of daemon-private storage layout.
- No dual-backend runtime that can fall back between `library` and `arsd`.
- No expansion of security scope, phases, or deployment prerequisites beyond what the usable integration needs.

### 15.2 Non-approvals (standing, unchanged)

This Spec approves none of: source/test/dependency/lock changes; the implementation plan; commit/push/PR/merge; Git branch/worktree operations; network or GitHub access; package installation; daemon start, socket connection, `server_info`, or `submit`; real AGENT/ACP execution; Gateway, Feishu, Temporal, Worker, service, config, restart, or deploy actions; write-capable roles; real delivery; production traffic; turning `arsd` on; or Sachima D2+ implementation.

`docs/roadmap/boundary-register.md` non-approvals remain in force in full.

## 16. Implementation-plan handoff criteria and open evidence gates

### 16.1 Handoff criteria

The implementation plan may be written once this Spec is reviewed and accepted, and it must:

1. Slice the work so each slice is independently reviewable and leaves `fake` green and `arsd` default-off.
2. Order the pin/mirror/drift-lock migration **before** any behavioral change, so the drift locks fail loudly rather than silently passing against a stale pin.
3. Treat §11 legacy retirement as its own slice with its own stable code and its own tests, not as a side effect of the socket work.
4. Treat the `turn_dir` removal (§8.2) as a contract change with an enumerated consumer list, not a rename.
5. Keep every acceptance row in §14 mapped to a named slice; anything unmapped is either dropped explicitly or the plan is incomplete.
6. Name, for each slice, exactly which non-approvals it does not lift.

### 16.2 Open evidence gates

These are **not** blockers for this docs-only Spec. They are the honest list of what has not been proven and must be resolved by later named gates.

| Gate | What is unproven | Resolved by |
|---|---|---|

| E-2 Real-import compatibility | That the 0.7.1 distribution imports cleanly and its real symbols match every mirror | Drift-lock tests running against the installed extra in CI |
