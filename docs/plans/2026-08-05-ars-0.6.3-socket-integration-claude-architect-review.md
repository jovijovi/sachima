3. **接口抽象最小、可实现。**提议的 `SupervisorTurnBackend` 恰好是现有 `AgentRunSupervisorBackend` Protocol（`agent_run_supervisor_port.py:95-109`）+ dispatcher 侧 `run_turn`（`agent_run_supervisor_library_backend.py:596`）的并集，唯一新增是 `dispatch_ref`（stable request_id 的必要输入）。submit 型 `run_turn` 返回 `accepted`、可信终态走 `status()`/对账，与现有 port 机制兼容：dispatcher 的 milestone 在 accept 时落，终态由 port 的 `_sync_backend_state_locked` 幂等镜像（`agent_run_supervisor_port.py:740-762`），事件权威不分叉。single-flight 收窄到 submit 窗口 + 单活跃 Run 的双层约束已写明。

## 建议的最小修订（改方案文本，不改代码）

1. **§8.1 状态表补一行**："已 `create_or_attach`、尚无任何 Run 的绑定 → 本地 ledger 态 `running`"。port 在 create_or_attach 内会立即调 `status()`（`agent_run_supervisor_port.py:393-397`），若按"missing observation→读失败"字面实现，arsd 模式首次 attach 必然失败。
2. **§5.1 补 library→中立词表映射**：`completed→completed`、`timed_out→timed_out`、`interrupted→cancelled`、其余 `_TURN_FAILURE_STATUSES` 家族→`failed`、越界→`unknown`；并明确 `SupervisorTurnResult` 中 `source_ref` 为 repr 排除的私有定位符（turn_dir/run_id）、`run_ref` 为 safe 公共 ref。
3. **§6.3 明确 ledger 持久性**：`{run_id}-ephemeral` 不可像 library 的 `derive_ars_session_id`（`agent_run_supervisor_library_backend.py:342-346`）那样从 task_id 重推。需写明三选一：持久化私有 ledger、经 `session_list` + owner/namespace 恢复、或首切片显式声明"进程重启后 `attach_existing` fail-closed 不恢复"。
4. **§8.2 明确 kill 与 Session 的关系**：library 的 kill=abort+close（`:567-592`）；arsd 的 kill=run_cancel 之后 Session 是否随之 close、不 close 则由谁何时 close，需一句话定死。
5. **§7.3/D1 fixture 补一个角例**："空事件页且 `exhausted=False`"的适配决策——现有 projection 对空页强制 `resume_cursor=None, has_more=False`（`live_progress_projection.py:644-650` 与验证器 `:370-376`），适配器须定义该形状是重取、corrupt 还是不可能态。
